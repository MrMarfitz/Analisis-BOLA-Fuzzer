PENGUJIAN BARU

Uji akses. Pahami buktinya.

Bandingkan akses pemilik objek dengan pengguna lain, satu langkah pada satu waktu.

Baru pertama kali menggunakan BOLA Fuzzer?
  1. Pilih konfigurasi lab atau isi API pada lingkungan uji.
  2. Siapkan dua akun dengan identitas berbeda.
  3. Tentukan objek dan hak bacanya berdasarkan kebijakan yang diperiksa.
  4. Jalankan pengujian dan periksa bukti kedua respons.

Untuk presentasi: jalankan Mulai-Lab.cmd, pilih Lab kendaraan privat, lalu ikuti empat langkah. Ini mengirim HTTP nyata ke API lab sintetis, bukan hasil contoh.

Tool menerapkan kebijakan terkonfigurasi; tidak menemukan seluruh aturan bisnis sendiri. Akun pada formulir adalah akun target, bukan akun dashboard.

Konfigurasi awal memakai data sintetis lab. Hasil baru muncul setelah pengujian nyata.

LANGKAH 1 DARI 4

API mana yang akan diuji?

Masukkan alamat target dan cara aplikasi mendapatkan token login.

Alamat API target, terpisah dari dashboard. Gunakan lingkungan lab yang Anda kuasai.

Jalur POST untuk login pada API target.

Misalnya token atau data.access_token.

Pengaturan autentikasi lanjutan

Lab kendaraan dan crAPI memakai email; layanan kontrol memakai username. Token dikirim dengan skema Bearer.

Engine terhubung berarti dashboard aktif. Kesiapan API dan kredensial diperiksa saat pengujian.

Langkah 3

LANGKAH 3 DARI 4

Objek apa yang dibandingkan?

Tentukan sumber objek, endpoint pembaca, dan aturan akses terverifikasi.

01 · Ambil objek milik A

Atribut id pada objek pertama daftar JSON. Pastikan objek itu memang milik A.

02 · Baca objek yang sama

Nama di dalam kurung kurawal pada endpoint.

Untuk memastikan respons A dan B berisi objek yang sama. Beberapa lokasi dipisahkan koma.

03 · Tentukan izin dan bukti

Tentukan dari kebijakan aplikasi dan bukti kepemilikan, bukan dari keluaran scanner.

Wajib untuk indikasi objek privat. Pisahkan beberapa lokasi dengan koma.

Verifikasi identitas kedua sesi

Lab kendaraan memakai owner pada daftar terfilter. API lain dapat memakai /me dengan $.id.

Penemuan endpoint dari OpenAPI · opsional

Kandidat bukan temuan. Mapping objek dan kebijakan tetap perlu ditinjau. Evaluasi massal dataset menggunakan harness penelitian.

Belum ada kandidat.

Hanya endpoint yang cocok dengan konfigurasi mendapat kebijakan yang ditinjau. Kandidat lain dapat berakhir tidak konklusif.

Langkah 4

LANGKAH 4 DARI 4

Siap menjalankan pengujian?

Periksa target dan konfigurasi. Password serta token tidak ditampilkan di sini.

Pengujian mengirim HTTP sungguhan. Hasil berlaku untuk kasus dan kebijakan yang diuji. Lab bawaan memakai data sintetis.

Label acuan opsional dapat disiapkan di tab Evaluasi sebelum scan. Deteksi dan bukti tetap berjalan tanpa label.

Engine memproses permintaan. Tunggu respons API; belum ada keputusan akhir.
